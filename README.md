# BetterHome3D

**让 Agent 更会找模型、更少重复试错，让人更方便地调整 3D 家。**

BetterHome3D 面向想用 AI 设计、比较和反复调整室内空间的人，以及为他们工作的 Codex 等编码 Agent。你提供需求和参考图，Agent 负责选择现成模型、安排布局和配色；你在浏览器里看空间、拖家具、换款，直接在想修改的位置留下评论，再让 Agent 按评论继续调整。

项目将 **现成模型的检索经验、常见错误与已验证的实现方法** 写进 skill，并提供可运行的 **Three.js / WebGPU 脚手架**。Agent 复用这些经验和代码，用户直接使用预设好的评论、家具换款、拖拽与光线切换功能。

## 为什么使用 BetterHome3D？

### 1. 让 Agent 学会找现成模型，减少手工拼模型

找模型需要知道去哪搜、怎样描述形体、什么时候换关键词，以及怎样判断模型是否真的可用。项目包含[模型检索经验](references/model-sourcing.md)和可执行的搜索脚本：从参考图拆解轮廓与结构，使用英文短 query、分类和同义词筛选，先看预览，再检查尺寸、材质与下载格式。

沙发的软包、布料褶皱、植物等细节优先使用成熟资产。Agent 把工作放在找对模型、校正尺度和搭配空间上，减少用基础几何体从头拼家具的工作。

### 2. 复用正确做法，减少重复探索和 token 消耗

模型发灰或丢贴图、家具旋转轴不对、评论标记漂移、刷新丢失用户调整、多开预览页拖慢电脑——这些问题的处理方法和边界已经写进 skill，通用交互也已经实现。Agent 可以沿已有方法配置和检查，而不必每次重新生成整套查看器、查接口、试错和修补。

检索、评论和场景配置分别放在按需读取的说明中。新 Agent 可以从这些文件接手，不依赖完整聊天记录。目标是减少重复推理、代码生成和返工消耗；目前没有量化的 token 节省比例。

### 3. 使用 Three.js 的 WebGPU 后端，并带上实际的性能优化

脚手架使用真实 WebGPU 与 TSL 后处理，同时实现按需绘制、交互期间降低渲染分辨率、静止后恢复画质、静态阴影缓存，以及模型和贴图的复用与释放。Agent 也能读取性能检查方法，按具体瓶颈调整。

这些优化用于减少无效绘制和交互负载。WebGPU 仍属于 Three.js；相对 WebGL 查看器的实际提升需要在同模型、同画质和同设备下测量，不能仅凭后端名称承诺“快很多”。

### 4. 人可以直接参与设计，常用交互已经准备好

| 预设功能 | 对使用者的意义 |
| --- | --- |
| 空间 comment | 双击墙面或家具留言，Agent 能读取关联对象、位置和截图，处理后关闭评论。 |
| 快速比较多个模型 | 点击左侧候选缩略图原位换款，直接比较 Agent 已筛选好的家具。 |
| 拖拽与旋转家具 | 自己试摆，不必为每次位置调整都发一条指令；镜头支持 WASD 与方向键。 |
| 不同光线 | 切换清晨、中午、傍晚、黑夜，观察配色和材质在不同光照下的呈现。 |
| 在线更新 | Agent 修改后在原页面应用，保留当前镜头与仍适用的家具调整，准备失败时保留旧画面。 |

## 一个典型使用过程

1. **提出设计需求。** 例如：“按这张参考图布置横厅，工作区替代餐区，单椅给三个候选。”
2. **Agent 准备场景。** 选择并整理现成资产，配置布局、材质、灯光、候选和观察机位，运行脚手架。
3. **在空间里反馈。** 浏览各个角度、拖动家具、比较候选；双击墙面或家具写下“这里太空”或“这把椅子换一个”。
4. **让 Agent 继续修改。** 告诉它读取评论；它核对关联对象和截图，修改场景并在线发布，检查结果后关闭已完成评论。

这套流程适合需要多轮调整的室内设计、家具选型和空间展示原型。它不包含家具库或示例房间模型，不会根据照片自动还原户型，也不替代设计者对尺度、动线和美感的判断。模型检索、尺寸整理和视觉验收仍是实际工作的一部分。

[安装为 skill](#安装为-codex-skill)，或[直接生成第一个场景](#不安装-skill直接生成场景)。完整的光照、隐墙、导出与交互配置见[脚手架说明](references/scaffold.md)。

## 安装为 Codex skill

需要 Git；生成场景还需要 Python 3.10+、Node.js 20+ / npm，以及支持 WebGPU 的浏览器与 GPU。Three.js 锁定为 `0.185.1`，由 `npm ci` 安装。

```sh
git clone https://github.com/Shire31/betterhome3D.git \
  "${CODEX_HOME:-$HOME/.codex}/skills/threejs-rendering"
```

如果目标目录已经有同名 skill，先保留现有版本，不要覆盖未同步的改动。让 Codex 重新加载 skill 后可使用：

> 使用 $threejs-rendering，根据我的参考图创建新场景。复用现成模型和脚手架，配置家具候选、空间评论及在线更新。

其他 Agent 可以直接从 [SKILL.md](SKILL.md) 开始读取。必须保留整个仓库目录；仅复制 `SKILL.md` 无法运行生成器。模型检索说明和 Blendkit 搜索脚本随仓库提供，无需安装另一个 skill；搜索需要网络，下载受资产提供方的许可与访问条件约束。

## 不安装 skill，直接生成场景

```sh
git clone https://github.com/Shire31/betterhome3D.git
cd betterhome3D
python3 scripts/create_scene.py ../my-scene \
  --model /absolute/path/to/chair.glb --editable --name '我的场景'
cd ../my-scene
npm ci
npm run check
npm start
```

打开 <http://127.0.0.1:8768/>。输入模型须为包含贴图和缓冲的 GLB；完整房间模型省略 `--editable`。输出目录必须不存在，生成器不会覆盖已有项目。重复的 `--model` 创建独立方案，多件家具组合需编辑 `scene.js` 的 `assets`。

服务仅监听本机，不是面向公网的多人协作服务。已占用默认端口时，可在生成项目中运行 `python3 server.py --port 8770`。

修改生成项目中的场景和资产后运行：

```sh
npm run check
npm run publish:scene
```

在原页面确认新版本已应用；通用运行时代码或 HTML 升级仍需要重新加载页面。验证存储和发布服务可运行 `npm run check:server`；需要浏览器的验证及临时测试项目用法见脚手架说明。

## 当前边界

- 评论持久化到项目文件；家具移动、候选选择与镜头仅保留在页面会话，刷新前须按文档备份。
- 在线更新会准备新场景并提交，复杂场景可能短暂停顿，不是任意代码热替换。
- 家具比例、原点、朝向、候选缩略图、墙体标签及灯位需显式准备；没有自动布置或碰撞检测。
- WebGPU 不可用时明确报错，不静默退回 WebGL；性能须在目标设备、分辨率与资产规模下实测。
